# Phase 1 Data Model: Galería / Nuestro Trabajo — Managed Gallery Module

**Feature**: `016-gallery-module` | **Date**: 2026-10-10

Introduces one new persisted table (`gallery_items`) plus its shared types and two ephemeral UI-state
types. Existing tables are untouched.

---

## 1. GalleryItemRecord (new — persisted)

Persisted in production as `public.gallery_items` (migration `0007_gallery.sql`) and in demo mode as the
localStorage key `alpi:gallery:v1`.

| Field | Type | Rules (verbatim from spec/research) |
|-------|------|--------------------------------------|
| `id` | `string` (uuid) | Primary key; generated by the data source. |
| `title` | `string` | Optional, defaults to `""`; `overflow-wrap: anywhere` in the UI; empty title renders no caption. |
| `category` | `string` | Optional free-form text, defaults to `""`; admin suggests a curated set (NOSTRIL, HELIX, NAVEL, TITANIO, Otro); long text must wrap without horizontal scroll. |
| `imageUrl` | `string` | **Required**, non-empty (validated at create: `DataError("La imagen es obligatoria")`). Source = `uploadImage(file, { prefix: "gallery-" })`. |
| `isActive` | `boolean` | Defaults to `true` on create; `false` hides the item from public lists (RLS enforces this in production too). |
| `createdAt` | `string` (ISO) | Defaults to `now()`; not user-editable. |

DB column mapping (from `src/types/supabase.ts` `gallery_items` Row): `image_url`, `is_active`,
`created_at` — mapped to camelCase by `toGalleryItem` in the Supabase adapter (mirrors `toTeamMember`).

## 2. NewGalleryItemInput (new — creation input)

| Field | Type | Rules |
|-------|------|-------|
| `title?` | `string` | Trimmed; empty → stored as `""`. |
| `category?` | `string` | Trimmed; empty → stored as `""`. |
| `imageUrl` | `string` | Required; non-empty after trim. |

`isActive` is always set to `true` by the adapter on create; `id`/`createdAt` are generated by the data
source. A validation failure throws a typed `DataError` and creates nothing (no partial records).

## 3. GALLERY_SEED (new — demo seed)

In `src/lib/data/gallery.ts`: `GalleryItemRecord[]` reusing `public/images/featured-1..4.svg` with
`isActive: true`, fixed UUID-ish ids, and `category` values `HELIX`, `NOSTRIL`, `NAVEL`, `TITANIO`.
The local adapter seeds `alpi:gallery:v1` from it when the key is absent (mirrors `team.ts`).

## 4. DataStore operations (new)

| Method | Signature | Behavior |
|--------|-----------|----------|
| `listGalleryItems` | `(input?: { includeInactive?: boolean }) => Promise<GalleryItemRecord[]>` | Public path: active only. Admin passes `includeInactive: true`. |
| `createGalleryItem` | `(input: NewGalleryItemInput) => Promise<GalleryItemRecord>` | Validates `imageUrl`; sets `isActive: true`; persists; returns the record. |
| `toggleGalleryItemActive` | `(id: string) => Promise<GalleryItemRecord>` | Flips `isActive`; returns the updated record; `DataError("Imagen no encontrada")` if the id is missing. |
| `deleteGalleryItem` | `(id: string) => Promise<void>` | Removes permanently; `DataError` if missing. |

Realtime: every successful mutation publishes a `DataChangeEvent { resource: "gallery" }`
(`realtime.ts`, feature-015 infrastructure). Throwing mutations publish nothing.

## 5. Fallback

`listFallbackGalleryItems(): Promise<GalleryItemRecord[]>` exported from `store.ts` (mirrors services/team):
used by the public island only when the live read fails; the island shows a non-blocking notice.

## 6. Supabase types

`src/types/supabase.ts` gains a `gallery_items` table block (Row/Insert/Update/Relationships: [])
matching the migration, in the same snake_case style as `team_members`.

## 7. Ephemeral UI state (never persisted)

**AdminGalleryRowState**: per-card `idle | busy | error` (feature-015 pattern).

| Value | Meaning | Transition |
|-------|---------|------------|
| `idle` | Card at rest | default |
| `busy` | Upload/toggle/delete in flight for this card or the new-photo form; controls disabled, card dimmed (`class:busy` + `aria-busy`) | start of any mutation |
| `error` | Mutation failed; previous data retained; inline message shown | on reject; cleared on next attempt |

List also tracks `{ items, loaded, loading, error }` where `loading` only shows the placeholder while
`loaded === false` (first load). After first load, mutations patch `items` in place — never blanking the
grid (FR-009).

**LightboxState** (public): `{ open: boolean; index: number }` — which enlarged photo is shown; client
only; loop/navigation via index.

## 8. Relationships

```text
GalleryItemRecord ──(list, active)──▶ LandingGallery (landing-v2 #galeria + index "Nuestro trabajo")
GalleryItemRecord ──(list, all)────▶ AdminPanel "Galería" tab (grid + toggle + delete + create)
uploadImage("gallery-") ──────────▶ imageUrl
subscribeToDataChanges(["gallery"]) ──▶ LandingGallery (live refresh, no reload)
```
