# Phase 1 Data Model: Disponibilidad, Horarios Laborales y Bloqueos Avanzados

**Feature**: `017-availability-schedule-blocks` | **Date**: 2026-10-11

Introduces two new persisted tables (`availability_blocks`, `studio_schedule`), replaces the
`TimeBlock` domain type with the range-based `AvailabilityBlock`, adds the `StudioSchedule` types, and
introduces the schedule-aware availability engine. The legacy `time_blocks` table (0003) stays in the
database untouched; no existing table is dropped or altered.

---

## 1. AvailabilityBlock (new range-based — persisted)

Persisted in production as `public.availability_blocks` (migration `0008_availability_blocks.sql`) and in
demo mode as the localStorage key `alpi:availabilityblocks:v1`.

| Field | Type | Rules (spec FR-005…FR-011) |
|-------|------|------------------------------|
| `id` | `string` (uuid) | Primary key; generated by the data source. |
| `startDatetime` | `string` (ISO, local offset) | Required start instant (`timestamptz` `start_datetime`). |
| `endDatetime` | `string` (ISO, local offset) | Required end instant (`timestamptz` `end_datetime`); must be strictly after `startDatetime` (DB CHECK + adapter validation). |
| `reason` | `string` | Free text (spec `reason`); trim, may be `""`. Admin label "Motivo". |
| `isFullDay` | `boolean` | `false` → time-range block for `startDatetime`/`endDatetime`; `true` → full-day range. Defaults `false`. |
| `createdAt` | `string` (ISO) | Defaults to `now()`; not user-editable. |

**Range semantics**:
- Time-range block: covers exactly `[startDatetime, endDatetime)` on its date.
- Full-day block: covers every whole day whose local date is between the local date of `startDatetime`
  and the local date of `endDatetime` inclusive (single day when both are equal).
- Overlaps are allowed; the union of intervals is blocked and each row is independently listed/deletable.

**DB column mapping** (`supabase.ts` Row): `start_datetime`, `end_datetime`, `reason`, `is_full_day`,
`created_at` → camelCase via `toAvailabilityBlock` in both adapters.

### Migration copy step (from `time_blocks`)

For each legacy row: `start_datetime = localDateTime(block_date, time_slot)`,
`end_datetime = start_datetime + duration_minutes`, `reason = label`, `is_full_day = false`.

## 2. NewAvailabilityBlockInput

| Field | Type | Rules |
|-------|------|-------|
| `startDatetime` | `string` (ISO) | Required; non-empty. |
| `endDatetime` | `string` (ISO) | Required; `end > start` else `DataError("El fin debe ser posterior al inicio")`. |
| `reason?` | `string` | Trimmed; empty → `""`. |
| `isFullDay` | `boolean` | Defaults `false`. |

A validation failure throws typed `DataError` and creates nothing (no partial records).

## 3. StudioScheduleDay + StudioSchedule (new — persisted)

Persisted in production as `public.studio_schedule` (one row per weekday) and in demo as
`alpi:studioschedule:v1`.

| Field | Type | Rules |
|-------|------|-------|
| `weekday` | `"sun" | "mon" | "tue" | "wed" | "thu" | "fri" | "sat"` | Unique; DB stores `smallint` 0=Sunday…6=Saturday (`Date#getDay()`). |
| `isOpen` | `boolean` | `false` → closed day (no slots). |
| `openTime` | `"HH:mm" \| null` | Required (non-null) when `isOpen === true`; DB `time` column. |
| `closeTime` | `"HH:mm" \| null` | Required when open; must be strictly after `openTime` (DB CHECK + adapter validation). |

DB mapping (`supabase.ts` Row): `weekday`, `is_open`, `open_time`, `close_time`.

**Seed**: migration inserts seven rows from the current default hours (Lun–Sáb 11:00–20:00, Dom closed).
Demo seed mirrors that. RLS: public `select`; authenticated upsert/delete.

## 4. DataStore operations

| Method | Signature | Behavior |
|--------|-----------|----------|
| `listBlocks` | `(input?: { date?: string }) => Promise<AvailabilityBlock[]>` | All blocks; optional filter by a local date (`yyyy-mm-dd`) — blocks whose interval covers that date. |
| `createBlock` | `(input: NewAvailabilityBlockInput) => Promise<AvailabilityBlock>` | Validates `end > start`; persists; returns the record. |
| `deleteBlock` | `(id: string) => Promise<void>` | Removes permanently; `DataError` if missing. |
| `getSchedule` | `() => Promise<StudioSchedule>` | Returns the seven weekdays in stable order; missing days normalized to closed. |
| `updateSchedule` | `(input: StudioSchedule) => Promise<StudioSchedule>` | **Atomic**: validates all seven days (`close > open` and times required when open), then persists the whole schedule in one batch (single upsert in production / single write in demo); returns the normalized schedule. |
| `getBookedSlots` / `getBlockedSlots` | **Removed** | Superseded by the schedule-aware availability service (`getDayAvailability`); this guarantees `src/` no longer reads the legacy `time_blocks` table. |

Realtime: successful mutations publish `"blocks"` (`createBlock`/`deleteBlock`), `"schedule"`
(`updateSchedule`), `"bookings"` (`createBooking`/`updateBookingStatus`/`updateBookingSchedule`).
Throwing mutations publish nothing.

## 5. Availability engine (domain service + pure helpers)

**Pure module** `src/lib/utils/availability.ts` (framework-agnostic, mirrors `calendar.ts`) and a **domain
service** `src/lib/services/availability.ts` (components only call the service, constitution "Data
Access").

| Function | Signature | Behavior |
|----------|-----------|----------|
| `resolveSlotInterval` | `(date, slot, durationMinutes) => { start: Date; end: Date }` | Local `Date`s for `[slot, slot+duration)`. |
| `isSlotFree` | `(date, slot, durationMinutes, scheduleDay, bookings, blocks) => boolean` | In-window + no booking overlap + no block overlap (full-day blocks cover the whole local day). |
| `buildFreeSlots` | `(date, scheduleDay, bookings, blocks, { durationMinutes, stepMin }) => string[]` | Open-times window in 30-min steps, minus booked/blocked slots. |

Public **service** `getDayAvailability(date, durationMinutes): Promise<DayAvailability>` where
`DayAvailability = { date, slots: string[]; schedule?: StudioScheduleDay; closedReason?: "closed" | "blocked" | null }`
orchestrates `dataStore.getSchedule()`, `listBookings({ date })` (with service durations) and
`listBlocks({ date })`, then returns `buildFreeSlots(...)`. BookingFlow consumes this; the booking guard
re-runs it (`isSlotFree`) before persisting (FR-014).

## 6. Ephemeral UI state (never persisted)

**AdminScheduleRowState** (feature-015 pattern): per-weekday `idle | busy | error` for the schedule rows
and per-block `idle | busy (deleting) | error` for the block list. List state `{ loaded, loading, error,
schedule, blocks }` where the placeholder renders only while `loaded === false`; after first load every
mutation patches the arrays in place — never blanking the list (FR-010).

**Block form state**: `mode: "range" | "full_day"`, per-field values, and a `collisionNotice: string`
(non-blocking warning when a saved block overlaps existing appointments, FR-011).

## 7. Supabase types

`src/types/supabase.ts` gains `availability_blocks` and `studio_schedule` table blocks
(Row/Insert/Update/Relationships: []), hand-maintained, snake_case (`start_datetime`, `end_datetime`,
`reason`, `is_full_day`, `weekday`, `is_open`, `open_time`, `close_time`).

## 8. Relationships

```text

AvailabilityBlock ──(blocks)────────────────▶ availability engine → public free slots
StudioSchedule ────(edit)──────────────────▶ AdminSchedule island
StudioSchedule ────(read)──────────────────▶ availability engine (window definition)
```
