# Contract: SEO Layer (Metadata, Structured Data, Crawl Artifacts)

**Feature**: 014-seo-optimization · **Phase**: 1 (Design & Contracts)

Covers three surfaces: the `SEO.astro` component's rendered `<head>` tags, the JSON-LD emitted by
`BaseLayout`, and the crawl artifacts (`robots.txt`, sitemap). No client JavaScript is introduced.

## 1. `SEO.astro` component

**Props**

```ts
interface Props {
  title?: string;        // default: `<brand> — <tagline>` (STUDIO_PROFILE)
  description?: string;  // default: STUDIO_PROFILE.bio
  image?: string;        // default: default studio image (BRAND_LOGO), made absolute
  canonicalURL?: string; // default: <site> + Astro.url.pathname (absolute)
  type?: string;         // default: "website"
  noindex?: boolean;     // default: false → robots "index, follow"; true → "noindex, nofollow"
}
```

**Rendered tags (order-independent; all in `<head>`)**

- `<title>{title}</title>`
- `<meta name="description" content={description} />`
- `<meta name="robots" content={noindex ? "noindex, nofollow" : "index, follow"} />`
- `<link rel="canonical" href={canonicalURL} />` (absolute)
- OpenGraph: `og:title`, `og:description`, `og:image` (absolute), `og:type`, `og:url` (absolute),
  `og:site_name` (= brand)
- Twitter: `twitter:card` = `summary_large_image`, `twitter:title`, `twitter:description`,
  `twitter:image` (absolute)

**Rules**

- Every attribute value is non-empty; missing props are replaced by defaults (FR-006).
- `canonicalURL`, `og:image` and `twitter:image` MUST be absolute URLs.
- No duplicate `<title>`/`description`/`canonical`/`og:*` tags may exist elsewhere (BaseLayout must not
  render them once `SEO.astro` owns them).

## 2. `BaseLayout.astro`

- Props extended to `{ title?, description?, image?, type?, noindex? }`; forwarded to `SEO.astro`.
- Keeps charset, viewport, icons, theme-color and `generator`; removes the now-duplicated description
  and title tags.
- Emits exactly one JSON-LD block:
  `<script type="application/ld+json" set:html={JSON.stringify(buildLocalBusinessJsonLd())} />`.

## 3. JSON-LD (`src/lib/seo.ts` → `buildLocalBusinessJsonLd()`)

```jsonc
{
  "@context": "https://schema.org",
  "@type": ["LocalBusiness", "BeautySalon", "TattooShop"],
  "name": "<brand>",
  "url": "https://<site>/",
  "logo": "https://<site>/images/logo.png",
  "image": "https://<site>/<default-image>",
  "description": "<bio>",
  "telephone": "<phone>",
  "priceRange": "$$",
  "address": { "@type": "PostalAddress", "streetAddress": "<location>", "addressCountry": "MX" },
  "sameAs": ["https://instagram.com/<handle>"],
  "openingHours": "Mo-Sa 11:00-20:00",
  "potentialAction": {
    "@type": "ReserveAction",
    "target": { "@type": "EntryPoint", "urlTemplate": "https://<site>/booking", "actionPlatform": "https://schema.org/DesktopWebPlatform" }
  }
  // "geo": { "@type": "GeoCoordinates", "latitude": ..., "longitude": ... }  // ONLY when configured
}
```

- MUST be valid JSON and MUST NOT contain empty required values; `geo` is omitted when unset.

## 4. `robots.txt` (generated by `src/pages/robots.txt.ts`, `Content-Type: text/plain`)

```
User-agent: *
Allow: /
Disallow: /admin

Sitemap: <site>/sitemap-index.xml
```

- `<site>` comes from `import.meta.env.SITE` (absolute). The file is emitted at the site root at build.

## 5. Sitemap (`@astrojs/sitemap` in `astro.config.mjs`)

- `site` configured from `process.env.SITE || "https://alpiercing.com"`.
- Integration emits `sitemap-index.xml` (and `sitemap-0.xml`) on every build.
- `filter` excludes any URL containing `/admin`.
- Public pages included: `/`, `/landing-v2`, `/catalog`, `/booking`.

## 6. Non-goals

- No visible content, styling, route or behavior changes.
- No app/DB schema changes; no `dataStore` access; no client JavaScript.
- No analytics, no per-product/service structured data (out of scope for this feature).
