# Phase 1 Data Model: Payment Methods, Deposit Proofs & Appointment Review

**Feature**: `018-payment-methods-deposit` | **Date**: 2026-10-14

Introduces two new persisted tables (`payment_methods`, `booking_events`), extends the existing
`bookings` entity with payment fields and an expanded status set, and adds ephemeral UI-state types.
Existing tables (`services`, `team_members`, `gallery_items`, `availability_blocks`, `studio_schedule`)
are untouched.

---

## 1. PaymentMethod (new — persisted)

Persisted in production as `public.payment_methods` (migration `0009_payments_and_booking_proof.sql`) and
in demo mode as the localStorage key `alpi:paymentmethods:v1`.

| Field | Type | Rules |
|-------|------|-------|
| `id` | `string` (uuid) | Primary key; generated by the data source. |
| `type` | `PaymentMethodType` | One of `"pago_movil" \| "binance" \| "zelle" \| "transfer" \| "cash"`; DB `check` enforces the set. |
| `title` | `string` | **Required**, non-empty (trimmed) → `DataError("El título es obligatorio")`. |
| `details` | `Record<string, string>` | Whitelisted keys per type (see §3); stored as `jsonb`. Missing keys default to `""`. |
| `instructions` | `string` | Optional free text; trimmed; defaults to `""`. Long text wraps without horizontal scroll. |
| `isActive` | `boolean` | Defaults to `true` on create; `false` hides the method from the client flow (`is_active`). |
| `createdAt` | `string` (ISO) | Defaults to `now()`; not user-editable. |

DB column mapping (Supabase adapter `toPaymentMethod`): `title`, `details`, `instructions`, `is_active`,
`created_at`, `type` — snake_case → camelCase.

### 2. NewPaymentMethodInput (new — creation/patch input)

| Field | Type | Rules |
|-------|------|-------|
| `type` | `PaymentMethodType` | Required; validated against the set. |
| `title` | `string` | Required; trimmed non-empty. |
| `details` | `Record<string, string>` | Required per-type keys must be present and non-empty (see §3); trimmed. |
| `instructions` | `string` | Optional; trimmed; defaults to `""`. |

`isActive` is always set to `true` by the adapter on create; toggling is a separate operation. A
validation failure throws a typed `DataError` and creates nothing.

### 3. PaymentMethodType + field descriptors (new)

Defined in `src/lib/types/domain.ts` (`PaymentMethodType`) and `src/lib/utils/payments.ts`
(`PAYMENT_METHOD_FIELDS`). Each type lists the keys its dynamic form requests and which are required:

| Type | Label | Detail keys (required in **bold**) |
|------|-------|-------------------------------------|
| `pago_movil` | Pago Móvil | **Cédula/RIF**, **Teléfono**, **Banco**, Titular |
| `binance` | Binance Pay | **Pay ID**, Titular |
| `zelle` | Zelle | **Correo/Cuenta**, **Titular** |
| `transfer` | Transferencia | **Banco**, **Cuenta**, **Titular** |
| `cash` | Efectivo | Sede/Nota (optional) |

The descriptor drives both the admin form (`AdminPayments.svelte`) and the client display
(`BookingFlow.svelte`), so labels never drift between surfaces.

## 4. Booking (existing — extended)

Persisted as `public.bookings`; new columns added by migration 0009. Domain type stays in
`src/lib/types/domain.ts`.

| Field | Type | Rules |
|-------|------|-------|
| `id` | `string` (uuid) | Primary key; existing. |
| `createdAt` | `string` (ISO) | Existing. |
| `clientName` | `string` | Existing; required. |
| `clientWhatsapp` | `string` | Existing; required. |
| `clientEmail` | `string` | **Existing-and-optional** — displayed when present; not required by the booking flow. |
| `serviceId` | `string \| null` | Existing. |
| `serviceName` | `string` | Existing snapshot. |
| `priceCents` | `number` | Existing; integer cents ≥ 0. |
| `depositCents` | `number` | Existing; authoritative deposit in integer cents. |
| `date` | `string` (`yyyy-mm-dd`) | Existing. |
| `timeSlot` | `string` (`HH:mm`) | Existing. |
| `status` | `BookingStatus` | **Extended**: `PENDING \| CONFIRMED \| REJECTED \| COMPLETED \| CANCELLED`. |
| `notes` | `string?` | Existing. |
| `paymentMethodId` | `string \| null` | **New**; FK → `payment_methods.id` `ON DELETE SET NULL`; `null` when no deposit step. |
| `paymentMethodName` | `string` | **New**; captured snapshot (survives method edit/delete); defaults `""`. |
| `paymentReference` | `string` | **New**; client-entered reference; defaults `""`. |
| `paymentProofUrl` | `string` | **New**; public URL / data URL of the uploaded receipt; defaults `""`. |

DB-only convenience column `deposit_amount numeric(10,2)` is **generated always as
(`deposit_cents::numeric / 100`) stored** — read-only, never a second source of truth (constitution §IV).

### 5. NewBookingInput (existing — extended)

Adds optional `paymentMethodId?: string | null`, `paymentMethodName?: string`, `paymentReference?: string`,
`paymentProofUrl?: string`, and optional `clientEmail?: string`. When provided for a deposit-required
service, the adapter persists them verbatim and sets `status = PENDING`.

## 6. BookingEvent (new — persisted, append-only)

Persisted as `public.booking_events` (production) / `alpi:bookingevents:v1` (demo).

| Field | Type | Rules |
|-------|------|-------|
| `id` | `string` (uuid) | Generated. |
| `bookingId` | `string` (uuid) | FK → `bookings.id` `ON DELETE CASCADE`; required. |
| `fromStatus` | `BookingStatus \| null` | `null` for the initial creation event. |
| `toStatus` | `BookingStatus` | The resulting status. |
| `createdAt` | `string` (ISO) | Defaults to `now()`. |

Written automatically by the data layer on `createBooking` (`null→PENDING`) and on every
`updateBookingStatus` (`from→to`). Read back for audit via `listBookingEvents(bookingId)`; **write is
append-only** (no update/delete policies).

---

## 7. State transitions

```text
(none)  --createBooking-->  PENDING
PENDING --approveBooking-->  CONFIRMED
PENDING --rejectBooking-->   REJECTED      (releases slot)
PENDING --cancelBooking-->   CANCELLED     (releases slot)
CONFIRMED --completeBooking-> COMPLETED    (terminal, occupies)
CONFIRMED --cancelBooking--> CANCELLED     (releases slot)
REJECTED / CANCELLED / COMPLETED --(any)--> rejected with DataError("Reserva no encontrada" / illegal)
```

Slot occupancy (partial unique index `bookings_active_slot_key`): `PENDING`, `CONFIRMED`, `COMPLETED`
occupy; `REJECTED`, `CANCELLED` release. Every transition is logged in `booking_events`.

## 8. DataStore operations (new/changed)

| Method | Signature | Behavior |
|--------|-----------|----------|
| `listPaymentMethods` | `(input?: { includeInactive?: boolean }) => Promise<PaymentMethod[]>` | Public path: active only. Admin passes `includeInactive: true`. |
| `createPaymentMethod` | `(input: NewPaymentMethodInput) => Promise<PaymentMethod>` | Validates title + required type fields; forces `isActive: true`. |
| `updatePaymentMethod` | `(id, patch: Partial<NewPaymentMethodInput>) => Promise<PaymentMethod>` | Validates merged result; `DataError("Método de pago no encontrado")` if missing. |
| `togglePaymentMethodActive` | `(id) => Promise<PaymentMethod>` | Flips `isActive`; returns the record. |
| `deletePaymentMethod` | `(id) => Promise<void>` | Permanent delete; existing bookings keep their snapshot. |
| `listBookingEvents` | `(bookingId: string) => Promise<BookingEvent[]>` | Ascending by `createdAt`; append-only history. |
| `createBooking` | (extended) | Persists payment fields; logs `NULL→PENDING`. |
| `updateBookingStatus` | (extended) | Persists status; logs `from→to`. |

Realtime: successful method mutations publish `DataChangeEvent { resource: "paymentMethods" }`; booking
mutations already publish `"bookings"`. Throwing mutations publish nothing.

## 9. Supabase types

`src/types/supabase.ts` gains `payment_methods` and `booking_events` table blocks (Row/Insert/Update/
Relationships) plus the new `bookings` columns (`payment_method_id`, `payment_method_name`,
`payment_reference`, `payment_proof_url`, `deposit_amount` read-only) and the widened status comment.

## 10. Ephemeral UI state (never persisted)

**AdminPaymentRowState**: per-card `idle | busy | error` (feature-015/016 pattern) — drives `class:busy` +
`aria-busy` and inline errors without blanking the list.

**PaymentStepState** (client): `{ methods, loading, notice, selectedId, reference, proofFile, proofPreview,
proofUploading, error }` — local to `BookingFlow`.

**ReceiptLightboxState** (admin): `{ open: boolean }` for the enlarged proof overlay; open/close only,
`Esc` closes, focus restored to the trigger.

**AdminBookingDetailState**: `{ acting: "idle" | "approving" | "rejecting" | "notifying", error }` for the
modal's action buttons.

## 11. Relationships

```text
PaymentMethod ──(list, active)──▶ BookingFlow "Pago del adelanto" step
PaymentMethod ──(CRUD)──────────▶ AdminPanel "Métodos de Pago" tab (AdminPayments.svelte)
PaymentMethod ──(snapshot name)─▶ Booking (paymentMethodName, survives edit/delete)
Booking.paymentProofUrl ──▶ AdminBookingDetail receipt + lightbox
Booking ──(create/updateStatus)─▶ BookingEvent (null→PENDING, PENDING→CONFIRMED/REJECTED, …)
Booking.paymentReference/Url ──▶ AdminBookingDetail "Verificación de pago"
buildBooking{Confirmation,Rejection}Link ──▶ AdminBookingDetail "Notificar por WhatsApp"
uploadPaymentProofImage("proof-") ──▶ Booking.paymentProofUrl
subscribeToDataChanges(["paymentMethods","bookings"]) ──▶ live refresh (no reload)
```
