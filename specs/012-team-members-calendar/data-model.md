# Phase 1 Data Model: Team Members Module, Monthly Admin Calendar & Mobile UX

**Feature**: [spec.md](./spec.md) · **Date**: 2026-10-09 · **Phase**: 1 (Design & Contracts)

> **Nature**: adds one new entity (`TeamMember`) to the hybrid data layer, plus a **derived** monthly
> calendar view over the existing `Booking` and `TimeBlock` entities. `Booking`, `Product`, `Service`
> and `TimeBlock` keep their current shape. Money stays integer cents (no monetary fields are added).

## 1. Entity: TeamMember

A studio artist/staff member shown publicly. Type: `TeamMember` in `src/lib/types/domain.ts`
(seed in `src/lib/data/team.ts`).

| Domain field | SQL column | Type | Validation |
|--------------|-----------|------|------------|
| `id` | `id` | `string` (UUID) | PK, `default gen_random_uuid()`. Unique, stable identity. |
| `name` | `name` | `string` | REQUIRED, non-empty (trimmed length ≥ 1). |
| `role` | `role` | `string` | REQUIRED, non-empty (e.g. "Piercer", "Joyería"). |
| `avatarUrl` | `avatar_url` | `string` | Optional; `''` allowed. Public URL or `''` → placeholder. |
| `bio` | `bio` | `string` | Optional; `''` allowed. Short biography. |
| `instagramHandle` | `instagram_handle` | `string` | Optional; `''` allowed. Stored without `@`; link only when non-empty. |
| `isActive` | `is_active` | `boolean` | Default `true`. Public visibility flag. |
| `createdAt` | `created_at` | `string` (ISO) | `timestamptz`, `default now()`. List ordering key (ascending). |

### Creation input: `NewTeamMemberInput`

```ts
interface NewTeamMemberInput {
  name: string;
  role: string;
  avatarUrl: string;        // '' when no avatar
  bio: string;              // '' allowed
  instagramHandle: string;  // '' allowed, no leading '@'
}
```

`id`, `isActive` and `createdAt` are **not** part of the creation input: the `id` is generated by the
database (`gen_random_uuid()`), `is_active` defaults to `true`, `created_at` is `now()`. The demo adapter
generates the UUID with `crypto.randomUUID()`.

## 2. State: active / inactive / deleted

```
create (admin)  ───────────────►  isActive = true
                                     │
                    deactivate (admin)│ activate (admin)
                                     ▼
                                 isActive = false   (hidden from the public landing section,
                                                     still visible/manageable in admin)

delete (admin)  ───────────────►  row removed (no FK references team_members)
```

- The public landing lists **only** `isActive = true` members (FR-003).
- The admin Equipo list shows **all** members with their state (FR-005).
- `isActive` is a **soft** visibility toggle; **delete** is a hard removal with an admin confirmation step.

## 3. Persistence constraints

- `id uuid primary key default gen_random_uuid()`.
- `name text not null`, `role text not null`.
- `avatar_url`, `bio`, `instagram_handle` are `text not null default ''`.
- `is_active boolean not null default true`, `created_at timestamptz not null default now()`.
- RLS: public `SELECT where is_active = true`; authenticated `SELECT` (all) / `INSERT` / `UPDATE` / `DELETE`.
- Demo adapter enforces the same validation (name/role non-empty) before writing `alpi:team:v1`, and
  narrows/validates every stored record on read (`isTeamMember` guard).

## 4. Validation rules (all layers)

| Rule | Where | Failure behavior |
|------|-------|------------------|
| `name` non-empty | Admin form + adapter | Submit blocked / `DataError` "El nombre es obligatorio". |
| `role` non-empty | Admin form + adapter | Submit blocked / `DataError` "El rol es obligatorio". |
| `instagramHandle` normalized (strip leading `@`, trim) | Admin form + adapter | Stored without `@`; invalid/empty → no public link. |
| `avatarUrl` optional | Adapter | `''` allowed; the public card shows a placeholder. |
| Only active members publicly | Store query / RLS | Inactive members absent from the landing section. |
| `id` unique | DB PK | Insert error surfaced; no optimistic change. |

## 5. DataStore operations (interface extension)

```ts
listTeamMembers(input?: { includeInactive?: boolean }): Promise<TeamMember[]>;
createTeamMember(input: NewTeamMemberInput): Promise<TeamMember>;
updateTeamMember(
  id: string,
  patch: Partial<NewTeamMemberInput> & { isActive?: boolean },
): Promise<TeamMember>;
deleteTeamMember(id: string): Promise<void>;
```

- `listTeamMembers()` (no options) → **active only** (public).
- `listTeamMembers({ includeInactive: true })` → all rows (admin).
- `createTeamMember` → inserts; the DB generates the UUID `id`, `isActive` defaults to `true`; returns the
  created `TeamMember`.
- `updateTeamMember` → applies the patch (`isActive` may be toggled).
- `deleteTeamMember` → hard-deletes the row.

## 6. Derived view: monthly calendar

Not persisted — computed in `src/lib/utils/calendar.ts` from `listBookings()`, `listBlocks()` and the
service duration map.

### MON-01 · MonthDayCell

| Field | Type | Notes |
|-------|------|-------|
| `date` | `string` | local ISO `yyyy-mm-dd` |
| `dayNumber` | `number` | 1–31 |
| `inMonth` | `boolean` | `false` for the leading/trailing cells of the 6×7 grid |
| `isToday` | `boolean` | matches `localISODate(new Date())` |

`monthGrid(monthStart)` returns exactly **42** cells starting on the Monday of the week containing the
1st and ending on the Sunday of the week containing the last day.

### MON-02 · DaySummary

| Field | Type | Notes |
|-------|------|-------|
| `total` | `number` | non-cancelled appointments that day (badge count) |
| `pending` | `number` | `status === "PENDING"` |
| `confirmed` | `number` | `status === "CONFIRMED"` |
| `cancelled` | `number` | `status === "CANCELLED"` |

`dayStatusSummary(bookings, date)` builds this from the single bookings array.

### Relationships

- `MonthDayCell` ← calendar month; `DaySummary` ← `Booking[]` filtered by `date`.
- The day detail lists `Booking[]` for the selected date + `TimeBlock[]` for that date.
- Reschedule availability (`buildOccupancies` ∪ blocks) is unchanged from feature 006.

## 7. Migration

`supabase/migrations/0006_team_members.sql`:

1. `create table if not exists public.team_members (...)` with the columns/defaults above.
2. `alter table public.team_members enable row level security;` + policies:
   - `team_members select public` → `for select using (is_active = true)`;
   - `team_members select authenticated` → `for select to authenticated using (true)`;
   - `insert`/`update`/`delete` → `to authenticated`.
3. `grant all on public.team_members to anon, authenticated, service_role;`

No seed in production; the demo adapter seeds `alpi:team:v1` from `src/lib/data/team.ts`.

`src/types/supabase.ts` gains the matching `team_members` `Row`/`Insert`/`Update` block.
